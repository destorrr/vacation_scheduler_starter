# Vacation Scheduler — стартовый каркас

Стек: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL 16, Jinja2, Bootstrap, openpyxl.

## Включено
- 12 таблиц предметной области;
- UUID-ключи и ограничения целостности;
- сотрудник учитывается отдельно в каждой организации;
- один план отпусков сотрудника в кампании организации;
- несколько периодов на один план, продолжительность включительно считает PostgreSQL;
- оригинальные шаблооны версионируются и не перезаписываются;
- строки Т-7 сохраняются как снимок листа и номера строки;
- Docker Compose для приложения и PostgreSQL;
- авторизация по логину и паролю (Argon2);
- роли `central_hr` и `responsible`;
- серверная проверка членства пользователя в организации;
- CSRF-защита форм входа и выхода;
- сессионная cookie с настраиваемым флагом Secure;
- CLI-команда создания первого центрального HR.

## Запуск
1. Скопируйте `.env.example` в `.env`.
2. Задайте уникальные длинные `SECRET_KEY` и `POSTGRES_PASSWORD`.
3. Для HTTPS установите `SESSION_HTTPS_ONLY=true`; за reverse proxy включите HTTPS.
4. Запустите `docker compose up -d --build`.
5. Создайте начальную миграцию: `docker compose exec app alembic revision --autogenerate -m "initial schema"`.
6. Примените миграцию: `docker compose exec app alembic upgrade head`.
7. Создайте первого администратора: `docker compose exec app python -m app.cli create-admin`.
8. Откройте `http://localhost:8000` и войдите созданной учётной записью.

## Роли и доступ
- `central_hr` видит все активные организации.
- `responsible` видит только организации, связанные с ним через `user_organizations`.
- Проверка доступа к организации выполняется на сервере; скрытие ссылок в интерфейсе не считается защитой.
- Создание пользователей и назначение организаций пока выполняются на уровне БД/административных процедур; экран управления пользователями будет отдельным этапом.

## Важно
Это развиваемый каркас, не готовая система. Импорт/сопоставление строк Excel и заполнение копии Т-7 будут реализованы далее. Не публикуйте приложение в интернет без HTTPS и reverse proxy. Не храните реальные пароли в Git. Не добавляйте тестовые пароли в исходный код.
