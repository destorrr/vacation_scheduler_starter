# Vacation Scheduler — стартовый каркас

Стек: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL 16, Jinja2, Bootstrap, openpyxl.

## Включено
- 12 таблиц предметной области;
- UUID-ключи и ограничения целостности;
- сотрудник учитывается отдельно в каждой организации;
- один план отпусков сотрудника в кампании организации;
- несколько периодов на один план, продолжительность включительно считает PostgreSQL;
- оригинальные шаблоны версионируются и не перезаписываются;
- строки Т-7 сохраняются как снимок листа и номера строки;
- Docker Compose для приложения и PostgreSQL;
- главная страница и `/health`;
- конфигурация Alembic для автогенерации миграций.

## Запуск
1. Скопируйте `.env.example` в `.env`.
2. Задайте уникальные длинные `SECRET_KEY` и `POSTGRES_PASSWORD`.
3. Убедитесь, что пароль в `DATABASE_URL` совпадает с `POSTGRES_PASSWORD`.
4. Запустите `docker compose up -d --build`.
5. Создайте миграцию: `docker compose exec app alembic revision --autogenerate -m "initial schema"`.
6. Примените: `docker compose exec app alembic upgrade head`.
7. Откройте `http://localhost:8000`, проверка API — `http://localhost:8000/health`.

## Важно
Это каркас, не готовая система. Авторизация, проверка прав, импорт/экспорт Excel и полноценные экраны будут реализованы далее. Не публикуйте приложение в интернет без HTTPS и reverse proxy. Не храните реальные пароли в Git. Сопоставление сотрудника со строками Т-7 должно дополнительно проверять принадлежность сотрудника организации шаблона на уровне сервиса.
