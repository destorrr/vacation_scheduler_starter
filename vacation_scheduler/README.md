# Vacation Scheduler — стартовый каркас

Стек: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL 16, Jinja2, Bootstrap, openpyxl.

## Включено
- 12 таблиц предметной области;
- отдельный учёт сотрудников в каждой организации;
- несколько периодов отпуска на один план, календарная продолжительность включительно;
- неизменяемые оригиналы Excel-шаблонов с версиями;
- авторизация Argon2, роли `central_hr` и `responsible`, CSRF-защита;
- серверная проверка доступа к организациям;
- интерфейс центрального HR для создания организаций, кампаний, ответственных и назначения доступа;
- загрузка версионируемых оригинальных Excel-шаблонов Т-7;
- извлечение строк сотрудников по русскоязычным заголовкам столбцов;
- предварительное сопоставление по табельному номеру и ФИО, ручная проверка совпадений;
- аудит создания и изменения учётных записей;
- Docker Compose и начальная миграция Alembic.

## Первый запуск
1. Скопируйте `.env.example` в `.env`.
2. Установите уникальные `SECRET_KEY` (не менее 32 случайных символов) и `POSTGRES_PASSWORD`.
3. Проверьте, что `DATABASE_URL` содержит те же имя БД, пользователя и пароль, что и параметры PostgreSQL.
4. При работе за HTTPS reverse proxy установите `SESSION_HTTPS_ONLY=true`.
5. Выполните `docker compose up -d --build`.
6. Примените схему: `docker compose exec app alembic upgrade head`.
7. Создайте первого администратора: `docker compose exec app python -m app.cli create-admin`.
8. Откройте приложение на порту 8000 и войдите созданным пользователем.

## Управление доступом
- Центральный HR видит все активные организации и управляет учётными записями ответственных на странице «Пользователи».
- Ответственный видит только назначенные ему организации.
- Пользователь может быть назначен сразу на несколько организаций.
- Для каждого ответственного требуется минимум одна активная организация.
- Центральный HR может деактивировать учётную запись или установить новый пароль.
- Изменения учётных записей и назначений фиксируются в `audit_log`.

## Миграции
Миграция `0001_initial_schema` создаёт исходную схему из SQLAlchemy metadata как bootstrap для чистой БД. Это одноразовая начальная миграция. После её применения все последующие изменения структуры нужно оформлять обычными явными Alembic-миграциями, не переписывая уже применённые ревизии.

## Ограничения текущего этапа
Создание организаций и кампаний доступно центральному HR. Ответственные загружают оригинальные шаблоны Т-7 в свои кампании; система сохраняет версии оригиналов, извлекает строки сотрудников и предлагает сопоставление по табельному номеру и ФИО. Неоднозначные и новые записи требуют ручного решения. Для сопоставленных сотрудников доступны ввод нескольких периодов отпуска (даты начала и окончания), удаление периода и формирование копии оригинального Excel-шаблона. Для стандартного шаблона Т-7 общая продолжительность периодов записывается в столбец E, а все запланированные даты с продолжительностью — одной строкой в столбец G. Если периодов больше, чем предусмотрено в шаблоне, экспорт останавливается с понятной ошибкой; периоды не отбрасываются. Перед публикацией в интернете необходимы HTTPS, reverse proxy и корректные секреты окружения.


## Ввод периодов и экспорт
1. Откройте кампанию организации и загрузите исходный Excel-шаблон.
2. Проверьте автоматическое сопоставление строк с сотрудниками; все неоднозначные строки сопоставьте вручную.
3. Перейдите в раздел «Ввод периодов и экспорт Excel».
4. Добавьте для каждого сотрудника все периоды: дату начала и дату окончания. Продолжительность считается включительно в календарных днях.
5. Сформируйте файл. Приложение создаёт отдельную копию актуального оригинала, заполняет связанные строки сотрудника и сохраняет готовый файл в разделе выгрузок.

Экспорт сохраняет структуру и оформление книги через openpyxl, включая листы и объединения ячеек. Исходный файл не перезаписывается. Поддерживаются `.xlsx` и `.xlsm` (макросы сохраняются). Перед эксплуатацией необходимо проверить распознавание заголовков на оригинальном шаблоне каждой организации: если подписи колонок отличаются от поддерживаемых вариантов, потребуется добавить их в app/excel/exporter.py.


## Идентификация сотрудников
В пределах одной организации сотрудник идентифицируется только по нормализованному ФИО. Табельный номер относится к отдельной должности/строке Т-7 и хранится в `template_rows.personnel_number`; он не участвует в поиске, создании и сопоставлении сотрудников. Если одинаковое ФИО встречается в нескольких строках с разными табельными номерами, эти строки связываются с одной записью сотрудника, а периоды отпуска вводятся один раз. Совпадение ФИО разных физических лиц намеренно не различается.
